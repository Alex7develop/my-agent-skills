# Test-Driven Development

Код без тестов, написанный "с ходу", кажется быстрее, но перекладывает
проверку корректности на пользователя. Этот навык заставляет доказывать
корректность тестом на каждом шаге.

## Процесс: Red → Green → Refactor

1. **Red.** Написать один тест, который описывает следующий кусок нужного
   поведения. Запустить и убедиться, что он падает по правильной причине
   (не из-за опечатки/синтаксической ошибки).
2. **Green.** Написать МИНИМАЛЬНЫЙ код, чтобы тест прошёл. Не решать сразу
   всю задачу — только то, что покрыто текущим тестом.
3. **Refactor.** Пока все тесты зелёные — убрать дублирование, улучшить
   имена, упростить структуру. Не менять поведение на этом шаге.
4. Повторять цикл, пока критерии готовности (из спеки, если она есть) не
   покрыты тестами.

## Что покрывать тестами (пирамида, примерный ориентир 80/15/5)

- **80% — unit-тесты.** Быстрые, изолированные, для основной бизнес-логики.
- **15% — интеграционные.** Стыки модулей, реальные (или близкие к реальным)
  зависимости.
- **5% — end-to-end.** Только критичные пользовательские сценарии.

## Принципы

- **DAMP > DRY в тестах.** Тест должен быть читаемым сам по себе даже с
  повторением, а не максимально сжатым через общие хелперы — тест, который
  нужно "распаковывать", чтобы понять, что он проверяет, вреден.
- **Один тест — одна причина упасть.** Если тест проверяет 5 вещей сразу,
  его провал не говорит, что именно сломалось.
- **Тестировать поведение, а не реализацию.** Рефакторинг внутренней
  структуры не должен ломать тесты, если внешнее поведение не изменилось.
- **Баг-фикс начинается с теста, который воспроизводит баг.** Сначала
  красный тест на баг, потом фикс, потом зелёный — это гарантия, что баг не
  вернётся незамеченным.

## Чек-лист перед тем, как считать задачу закрытой

- [ ] Каждый критерий готовности из спеки покрыт хотя бы одним тестом
- [ ] Тесты падали (red) до реализации — не написаны постфактум "для галочки"
- [ ] Нет тестов, которые проверяют детали реализации вместо поведения
- [ ] Все тесты зелёные после финального рефакторинга
